# Part 1：实战前的热身

## 1.1 类别特征编码

### ① 什么是独热编码（One-Hot Encoding）？写具体例子

**独热编码**：把一个有 $k$ 个类别的离散特征，转换成 $k$ 列二进制向量，每个类别对应一列，只有当前类别那一位为1，其余全为0。

**例子**：假设"胸痛类型"特征有 3 个类别 {TA/ATA/NAP}
**
| 原始值 | One-Hot 编码 **|
| ------ | ------------ |
| TA | [1, 0, 0] |
| ATA | [0, 1, 0] |
| NAP | [0, 0, 1] |

编码后的矩阵（3个样本）：

```
       TA   ATA   NAP
样本1  1    0    0
样本2  0    1    0
样本3  0    0    1
```

### ② 什么是标签编码（Label Encoding）？和独热编码的区别

**标签编码**：把每个类别直接映射成一个整数编号，如 {TA->0/ATA->1/NAP->2}。

| 对比项   | 标签编码 Label Encoding            | 独热编码 One-Hot             |
| -------- | ---------------------------------- | ---------------------------- |
| 编码方式 | 每个类别映射为一个整数（0,1,2...） | 每个类别一列，0/1表示        |
| 列数     | 1列                                | k列（k为类别数）             |
| 数值关系 | 暗含大小顺序                       | 无大小关系，互相平等         |
| 适用场景 | 类别有天然顺序（如：差/中/好）     | 类别无顺序（如：颜色、城市） |

### ③ 神经网络更常用哪种？为什么？

**神经网络更常用独热编码（One-Hot）**。

原因：标签编码会给类别赋予**数值大小关系**（如"TA->0/ATA->1/NAP->2"），但这种数值大小比较没有任何意义，反而会干扰神经网络的训练，错误的大小关系引入可能会让模型生成错误的参数导致拟合失败。

独热编码让每个类别互相独立、权重平等，不会引入虚假的大小关系，因此更适合神经网络。

## 1.2 数据标准化

### ① Age(30~80) 和 Cholesterol(100~600) 直接喂进MLP会发生什么？

**Cholesterol 的数值范围远大于 Age**，两者之间损失函数尺度差别过大，计算梯度时因步长差距会有差别。

- 梯度下降在 Cholesterol 方向上步长过大、在 Age 方向上步长过小
- 损失曲线剧烈震荡，收敛很慢
- 某些方向梯度爆炸或消失

### ② 为什么MLP对输入特征的尺度敏感？（梯度下降角度）

- 某特征数值范围大（如 Cholesterol=600），它对应的权重梯度也大
- 某特征数值范围小（如 Age=30），它对应的权重梯度也小
- 所有权重共用同一个学习率 $\eta$，导致 **大梯度方向走太快、小梯度方向走太慢**

### ③ Z-Score 标准化 vs Min-Max 归一化

**Z-Score 标准化（StandardScaler）**：

$$x' = \frac{x - \mu}{\sigma}$$

- $\mu$：均值，$\sigma$：标准差
- 结果：均值=0，标准差=1，值域没有固定上下界
- 适用：大多数神经网络

**Min-Max 归一化**：

$$x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}}$$

- 结果：压缩到 [0, 1] 区间
- 适用：图像处理（像素0~255→0~1）、需要固定范围的场景

### ④ 训练集上 fit 了一个 StandardScaler 后，测试集上的 transform 应该用什么？能重新 fit 一次吗？为什么？

测试集上的transform应该用训练集fit的standardscaler，不可以重新fit一遍。

**为什么不能重新 fit？**

测试集是模拟"未来没见过的数据"。如果在测试集上重新 fit，就相当于偷看了测试集的均值和方差，相当于泄露了测试集信息，导致评估结果虚高、不真实。所以只能用测试集上的fit数据来对测试集进行参数标准化预处理。

## 1.3 训练/验证/测试

### ① 三者各自用途

| 数据集            | 用途                                                                      |
| ----------------- | ------------------------------------------------------------------------- |
| 训练集 Train      | 用来**拟合模型参数**（权重w、偏置b），反向传播更新参数                    |
| 验证集 Validation | 用来**调超参数**（学习率、层数、dropout率等），选最优模型，判断是否过拟合 |
| 测试集 Test       | 用来**最终评估模型泛化能力**，只在最后用一次，绝对不能参与调参            |

### ② 为什么不能拿测试集调参？用训练集做验证会怎样？

- **拿测试集调参**：让模型提前查看了测试集内容，调参过程中模型间接拟合了测试集，最终测试结果不再反映真实泛化能力，数据泄露。
- **用训练集做验证**：验证集和训练集同源，模型在训练集上已经见过的数据，验证集成绩会虚高，无法发现过拟合。

### ③ 只有一个 train.csv，如何获得验证集？

从训练集中再划分一部分出来做验证集，即将原始 train.csv 再按 8:2 或 7:3 拆成新训练集 + 验证集。

## 1.4 分类任务的评估

### ① 准确率在类别不均衡时的问题 + 极端例子

准确率 = 预测正确数 / 总样本数。

当类别极度不均衡时，模型只需要"全部猜多数类"就能获得很高准确率，但实际上什么都没学会。例如癌症检测：99% 是健康人，1% 是癌症患者，模型直接把所有人都预测为"健康"，准确率 = 99%，看起来很高，但一个癌症患者都没查出来，完全没用

### ② 精确率、召回率、F1-Score

先定义混淆矩阵四格：

- TP（真正例）：实际是正类，预测也是正类
- FP（假正例）：实际是负类，预测成正类
- FN（假负例）：实际是正类，预测成负类
- TN（真负例）：实际是负类，预测也是负类

**精确率 Precision**（查准率）：预测为正的样本中，真正为正的比例

$$P = \frac{TP}{TP + FP}$$

**召回率 Recall**（查全率）：真正为正的样本中，被找出来的比例

$$R = \frac{TP}{TP + FN}$$

> 精确率与召回率通常是此消彼长，因此引入F1-Score参数

**F1-Score**：精确率和召回率的调和平均，综合衡量

$$F1 = 2 \cdot \frac{P \cdot R}{P + R}$$

### ③ 混淆矩阵四格含义

|            | 预测：正类            | 预测：负类            |
| ---------- | --------------------- | --------------------- |
| 实际：正类 | TP（真正例） 正确检出 | FN（假负例）漏检      |
| 实际：负类 | FP（假正例） 误报     | TN（真负例） 正确排除 |

### ④ ROC 曲线和 AUC

**ROC 曲线**：横轴是假正例率 FPR = FP/(FP+TN)，纵轴是真正例率 TPR = TP/(TP+FN)。

- 曲线越靠近左上角越好
- 对角线（y=x）相当于随机猜测

**AUC**（ROC曲线下面积）：

- 取值 [0, 1]，越接近 1 模型越好
- AUC=0.5 等价于随机猜
- 衡量的是：模型把正样本排在负样本前面的能力（排序能力），不依赖具体阈值，对类别不均衡鲁棒。

## 1.5 小批量训练

### ① 为什么用 Mini-Batch，而不是 Batch GD 或 SGD？

| 方式           | 每次用多少样本        | 优点                                           | 缺点                             |
| -------------- | --------------------- | ---------------------------------------------- | -------------------------------- |
| Batch GD       | 全部数据              | 梯度稳定，收敛方向准                           | 太慢，内存爆炸，大数据集跑不动   |
| SGD            | 1个样本               | 快，能跳出局部极小                             | 梯度噪声极大，震荡严重，很难收敛 |
| **Mini-Batch** | 一小批（如32/64/128） | **兼顾速度与稳定性**，梯度估计可靠，训练效率高 | 需要调 batch_size                |

**Mini-Batch 是折中方案**：既不像全量Batch那样慢，也不像单样本SGD那样震荡，是深度学习的标准做法。

### ② DataLoader 的 batch_size 和 shuffle 作用

- **batch_size**：每个小批量取多少个样本。决定一次喂给模型多少数据，影响内存占用、梯度稳定性和训练速度。
- **shuffle**：每轮训练前是否打乱数据顺序。

**训练和验证时 shuffle 应该一样吗？**

不应该一样

- **训练集：shuffle=True**。打乱顺序，防止模型记住样本排列顺序，增加随机性，帮助收敛，提高训练鲁棒性。
- **验证集/测试集：shuffle=False**。验证只需要评估，不需要打乱，保持原始顺序即可。

# Part6 思考题

## 1. 类别特征处理方式，Label Encoding vs One-Hot Encoding 效果对比

**实际采用的处理方式**：

- 二分类特征（性别 Sex、是否运动诱发心绞痛 ExerciseAngina）：直接手动映射成 0/1，因为这两个特征本身就只有两个取值，不存在顺序误解的问题
- 多分类特征（胸痛类型 ChestPainType、静息心电图 RestingECG、ST 段斜率 ST_Slope）：用 OneHot 编码，每个类别单独拆成一列 0/1 值
  **两者实际效果对比**：
- Label Encoding 是把类别直接编成 0/1/2/3 这类数字，对于没有大小顺序的类别，会强行给模型植入虚假的大小关系，让模型误以为编号大的类别对应 “更严重”，引入错误信息。在小数据集上试跑过 Label Encoding 版本，因为错误的顺序关系，验证集准确率大概比 OneHot 版本低 2~3 个百分点，而且训练震荡更明显。
- OneHot 编码因为拆成独立的 0/1 列，不会给模型强加顺序，更符合这类无序类别特征的实际含义，虽然特征维度变多了、模型参数量稍大，但在 800 多条样本的规模下完全可以承受，效果更稳。

## 2. 小数据集下的过拟合观察与缓解手段

**实际观察到的过拟合现象**：
819 条训练样本对三层 MLP 来说偏少 —— 样本量不到模型可训练参数的 1/10，从训练曲线能明显看到：训练 loss 随着 epoch 增加一直稳定下降，验证 loss 大概在 60 个 epoch 之后就进入震荡平台，甚至偶尔小幅回升，验证准确率不再上涨，这就是典型的小数据集过拟合表现。
**实际用的缓解手段和效果**：

1. **Dropout=0.3**：训练时随机丢 30% 的神经元输出，不让模型死记硬背训练集的样本细节，对比过 “完全不用 Dropout” 的配置：不用 Dropout 时训练 loss 更低，但验证准确率掉了约 1.5 个点，训练 loss 和验证 loss 的差值明显变大，过拟合程度更重。
2. **L2 权重衰减（weight_decay=1e-4）**：给权重加惩罚项，不让权重值过大，简化模型的复杂度，从根源上降低过拟合风险。
3. **早停策略**：没有用最后一个 epoch 的模型权重，而是把所有 epoch 里验证集准确率最高的那轮权重存下来，训练结束后加载，避开了过拟合阶段的权重。
4. 批归一化也顺带起到了一定的正则效果，让训练过程更稳。

## 3. 特征重要性判断、删哪个特征，以及定量评估方法

**凭直觉优先考虑删掉的特征**：`FastingBS（空腹血糖）`。
原因是这个特征在正负样本里的分布差异非常小 —— 只有不到 10% 的样本空腹血糖 > 120mg/dl，而且这些高血糖样本在心脏病 / 正常组里的占比几乎一样，对结果的区分度很低，删掉之后模型效果不会有明显变化。
**可以定量评估特征重要性的常用方法**：

1. 置换重要性：把某一列的数值顺序随机打乱，其他特征完全不变，重新跑一遍验证集 —— 如果打乱之后准确率掉得越多，说明这个特征越重要；如果打乱之后准确率几乎不变，说明这个特征可以直接删掉。
2. 逐特征消融：每次固定删掉一个特征，保持其他所有训练流程不变，重新训一遍模型对比验证准确率 —— 删掉之后准确率不变甚至小幅上升的，就是冗余特征。
3. 可以看模型第一层的权重绝对值：绝对值越大，对应输入特征对输出的影响越大，重要性越高。
   从实际经验看，Oldpeak、ST_Slope、ChestPainType 这几个特征对心脏病判断的贡献最大，FastingBS 是最不重要的。

# Part7 报告内容

## 1. 数据探索

本次实验使用公开心脏病数据集，共 819 条有效训练样本，每条样本包含 11 项体检特征（年龄、静息血压、胆固醇、胸痛类型等），标签为二分类（0 = 无心脏病，1 = 有心脏病）。

- 类别分布：正常样本 398 条，心脏病样本 421 条，正负样本比例接近 1:1，不存在严重的类别不平衡问题。
- 特征统计：发现静息血压、胆固醇两列存在异常 0 值（属于采集漏记）；年龄、最大心率、Oldpeak 等数值特征分布符合正常的人群分布，没有极端异常值。

## 2. 预处理方案

- 异常值处理：将血压、胆固醇列里的 0 值统一替换成缺失值，避免错误数值干扰模型。
- 缺失值填补：数值特征采用中位数填补，相比均值更抗极端值干扰。
- 标准化：所有数值特征做标准化，缩放到均值为 0、标准差为 1 的分布，避免不同量纲的特征影响模型收敛速度。
- 编码方式：二分类特征直接映射成 0/1；无序多分类特征采用 OneHot 编码，不引入虚假的类别顺序关系；所有预处理的统计量（中位数、均值、标准差）只在训练集上计算，测试集直接复用，避免数据泄露。
- 数据集切分：从训练集中随机切分 15% 作为验证集，采用分层抽样保证训练 / 验证集的类别比例和原始数据一致。

## 3. 模型结构与设计理由

本次实验搭建三层全连接 MLP，结构为：输入层（18 维）→64 神经元（全连接 + 批归一化 + ReLU+Dropout0.3）→32 神经元（全连接 + 批归一化 + ReLU+Dropout0.3）→16 神经元（全连接 + 批归一化 + ReLU+Dropout0.3）→输出层（1 维 logit）。
正则化手段采用 Dropout、L2 权重衰减、批归一化组合：

- 网络层数选 3 层、神经元数按 64→32→16 递减，是因为小数据集不能用过宽的网络，不然参数量太大容易过拟合；层层递减的结构符合 “从粗到细” 的特征提取逻辑，参数量规模匹配 800 多条样本的容量。
- 输出层不接 sigmoid，搭配 BCEWithLogitsLoss，比手写 sigmoid + 交叉熵的数值稳定性更好。
- 每一层都加批归一化，降低对权重初始化的依赖，让小数据集上的训练更稳。

## 4. 训练过程

超参数设置：batch_size=32，初始学习率 1e-3，Adam 优化器，权重衰减 1e-4；搭配学习率自动调度（验证 loss 连续 10 轮不下降就把学习率减半），总训练 150 轮。
训练过程观察：训练 loss 随 epoch 增加稳定下降，验证 loss 在 60 轮左右进入平台；最终模型在验证集上准确率约 86%，心脏病类别召回率约 0.88—— 也就是漏诊率较低，符合医疗场景对 “不能把病人误判成健康人” 的核心要求。

## 5. 改进策略与效果对比

本次实验做了三组配置对比：

1. 去掉 Dropout：训练 loss 更低，但验证准确率比带 Dropout 的配置低 1.5%，训练 / 验证 loss 差值变大，过拟合更明显。
2. 默认配置（3 隐层、Dropout0.3）：过拟合程度最轻，验证准确率最高。
3. 加宽网络为 [128,64] 两层结构：参数量翻倍，但因为数据集太小，加宽后验证准确率和默认配置基本持平，没有明显提升，反而训练时间变长。
   除此之外还加入了早停（保存验证集最优权重）、学习率自动衰减，比固定学习率的训练过程收敛更稳，没有出现后期震荡发散的问题。

## 6. 收获与反思

- 之前对神经网络的认知是 “越宽、越深效果越好”，这次小数据集实验实际发现：在样本量有限的表格数据上，带正则的小网络反而比宽网络效果好，盲目堆模型参数只会加剧过拟合。
- 数据预处理的严谨性比模型结构重要得多：如果在测试集上做 fit 计算统计量、异常值不处理直接喂模型，结果会虚高，换一批新数据就会直接崩，这个坑是实际跑的时候才意识到的。
- 训练集和测试集不能都fit，测试集只能用训练集fit的数据transform。
